# Clysm IDE

Common Lisp の統合開発環境です。エディタ（`ui/editor/`）も、画面（`ui/`）も、評価する Lisp も、すべて Common Lisp で書かれ、Clysm で WebAssembly にコンパイルされています。JavaScript で書いた部分は、ページを読み込む数行と、どのアプリケーションでも共通の Electron のシェル（`ui/electron/`）だけです。

```
$ examples/ide/build.sh && python3 -m http.server -d build/ide          # ブラウザ
$ examples/ide/build-desktop.sh && (cd build/ide-desktop && npm start)  # Electron
$ (cd build/ide-desktop && npx electron . ~/my-project)                 # フォルダを開いて起動
$ tests/ide/desktop.sh                                                  # テスト（Electron）
```

ブラウザ版はファイルを localStorage に保存します。デスクトップ版はコンピュータのフォルダをプロジェクトとして開き、評価するコードからも `open` や `directory` でそのフォルダのファイルを読み書きできます（作業ディレクトリはプロジェクトのフォルダです）。

評価は IDE とは別の **world**、つまり IDE と同じイメージを Web Worker で動かしたものの中で行います。評価したコードが何をしても IDE は壊れず、world は何をしていても終わらせて新しく始められます。

## できること

- **評価**: カーソルのトップレベルのフォーム（または選択範囲）、カーソルの前の式、ファイル全体。評価は IDE とは別の world（Web Worker の中の Clysm のイメージ）で行い、フォームはその場で WebAssembly にコンパイルされます。ファイルの `in-package` に従ってパッケージを選びます。
- **REPL**: 値、出力（`format t` など）、`*` `**` `***`、入力の履歴。Return は式が閉じていれば評価し、閉じていなければ改行します。
- **デバッガ**: エラーになると、状態の型とメッセージ、リスタート、バックトレースを表示し、選んだリスタートで計算を続けます（`restart-case` の `use-value` など）。デバッガが待っている間も REPL で評価できます。
- **中断**: 終わらない計算も ■ 中断 で止められ、デバッガで「評価を続ける」か「評価をやめる」を選べます。計算している間も IDE は動き続けます。スタックが尽きた計算は、IDE を巻き込まずに終わります。
- **world の再起動**: ↻ world で、評価している world を何をしていても終わらせ、新しく始めます。
- **インスペクタ**: REPL の値をクリックすると、リスト、ベクタ、ハッシュテーブル、構造体、CLOS のオブジェクト、シンボルの中を順にたどれます。
- **補完**: シンボルの名前（`pkg:name`、`:keyword` も）。候補が1つならそのまま入れ、複数なら一覧を出します。
- **引数リスト**: カーソルを関数呼び出しの中に置くと、その関数の引数リストがステータス行に出て、いまの引数が `[ ]` で示されます。
- **定義へ移動**: IDE で評価した定義、イメージに組み込まれた定義、開いているファイルとプロジェクトのファイルにある `(def… name` を探します。戻ることもできます。
- **describe**、**マクロの1段展開**
- ファイルのツリー、ファイルの定義の一覧、タブ、名前でファイルを開くパレット、保存
- キーは標準と Emacs（SLIME と同じ `C-c C-c` など）の2種類。折り返し表示

## キー

| 標準 | Emacs | |
|---|---|---|
| Mod-Return、C-c C-c | C-c C-c、C-M-x | フォーム（または選択範囲）を評価 |
| Mod-Shift-Return、C-c C-k | C-c C-k | ファイル全体を評価 |
| Mod-e | C-x C-e | カーソルの前の式を評価 |
| C-Space | C-M-i、M-Tab | 補完（一覧では ↑↓ と Return、Escape） |
| F12、M-. / M-, | M-. / M-, | 定義へ移動 / 戻る |
| F1 | C-c C-d d | describe |
| Mod-m | C-c C-m | マクロを1段展開 |
| Mod-j、C-c C-z | C-c C-z | REPL へ（REPL から戻るのも同じキー） |
| Mod-p | C-x C-f | ファイルを名前で開く |
| Mod-s | C-x C-s | 保存 |
| C-Tab、C-S-Tab、Mod-w | C-Tab、C-S-Tab | 次 / 前のタブ、タブを閉じる |

REPL では Return で評価、Shift-Return で改行、Mod-Return で（閉じていなくても）評価、↑↓（1行目と最後の行で）と M-p / M-n で履歴、Tab で補完します。

## 仕組み

| ファイル | 内容 |
|---|---|
| `world.lisp` | world の側: 評価、出力、デバッガ、中断、補完、引数リスト、describe、定義の場所、インスペクタ |
| `client.lisp` | IDE の側: world の起動と再起動、world とのやりとり、REPL のログ、評価中かどうか、デバッガ |
| `ide.lisp` | ファイル、バッファ、キー、画面のコンポーネント |
| `ide.css` | 見た目 |

**イメージ**: `build.sh` は `tools/build-repl.lisp` で、コンパイラを含むイメージ（約 12 MB）にフレームワーク、エディタ部品、IDE をコンパイルします。

**world**: IDE は自分では評価しません。起動すると、同じイメージを Web Worker でもう1つ動かします（`contrib/world/worker.js` が、ページでコンパイル済みの WebAssembly のモジュールを受け取って起動するので、0.4 秒ほどで起動します）。ワーカーの中のイメージは、ページがない（`document` がない）ことから自分が world だとわかり、画面を出す代わりに IDE からのメッセージを待ちます（`serve-world`）。評価するコードは別のヒープ、別のスレッドで動くので、

- 評価したコードがイメージを壊しても（`car` を定義し直しても）IDE はそのまま動きます。
- 終わらない計算の間も IDE の画面は止まりません。
- **↻ world** で、何をしていても world を終わらせ、新しい world を始められます（中断できない計算もこれで止まります）。新しい world には前の定義は残りません。

デスクトップ版の world は Node.js を持つワーカーなので、`open` や `directory` でコンピュータのファイルを使えます。作業ディレクトリはプロジェクトのフォルダです。

**やりとり**: IDE と world は、ワーカーのメッセージで S 式を送り合います（文字列、数、キーワード、リストだけ。`*read-eval*` は偽で読む）。IDE からは評価（`:eval`）、中断（`:interrupt`）、リスタートの選択（`:restart`）、問い合わせ（`:request`: 補完、引数リスト、describe、マクロ展開、定義の場所、インスペクタ）を送ります。world からは出力、値、デバッガ、評価の終わり、定義した名前とその場所、問い合わせの答えが届きます。world のオブジェクトは IDE に印字した文字列と番号で渡り、インスペクタはその番号で world に中身を尋ねます。

**評価は world の中の別の計算**: 評価は `js:async` で、それ自身の計算として走ります。待つことができるので、エラーではデバッガの内容を IDE に送り、リスタートが選ばれるまで計算を止めておけます。待っている間も、world は IDE の問い合わせや別の評価に答えます。計算がスタックを使い果たしても、world は生きています。

**中断**: 評価するコードは割り込みの検査付きでコンパイルされます（`sys::*interrupt-checks*`）。検査は関数の入口とループの先頭で呼ばれ、world の関数（`poll`）は 40 ミリ秒ごとに `js:await` でワーカーのイベントループに処理を譲ります。そのときに出力が IDE に送られ、IDE からのメッセージが届きます。中断の要求があれば、検査のところで `continue` リスタート付きでデバッガに入ります。

**ログ**: REPL の各行は `defmodel` のオブジェクトで、コンポーネントとして描かれます。出力が増えると、その出力の行だけが描き直されます。

## 制限

- 割り込みの検査がないコード（イメージに組み込まれた関数の中の長いループ）は ■ 中断 では止まりません。↻ world で止めてください。
- バックトレースは関数の名前だけで、フレームの変数は見られません。
- ASDF と Quicklisp はイメージに入っていません（ファイルを順に評価してください）。
- ブラウザ版のファイルは localStorage にあるので、world の `open` からは見えません。
- world は Web Worker で WebAssembly を止められる（JSPI）ブラウザ、Chrome / Edge 137 以降と Electron で動きます。
