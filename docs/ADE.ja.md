# Clysm の ADE 設計

ADE は Agentic Development Environment、人間と AI エージェントが同じ環境で開発する場を指す。
この文書は、Clysm の性質を使った ADE の設計と、その実装の進み具合を記す。

状態(2026-11-18): ステップ 1(ワールド)が実装済み。ステップ 2 以降は未着手。

## 中心の考え

**エージェントの作業対象をファイルではなく「生きているイメージ」にする。**

通常の ADE では、エージェントはテキストを編集し、ビルドし、ログを読む。
Clysm ではイメージ内のコンパイラが定義 1 つを Wasm モジュールにして即リンクするので、
エージェントは人間が SLIME でやることをそのまま行える。ファイルは結果の記録先になる。

## 用語

- **ワールド**: エディタとは別に動く Clysm のイメージ。ページのワーカーの中で動き、
  micros サーバーを持つ。評価はここで行う。この設計で付けた呼び名である
  ([contrib/world/README.md](../contrib/world/README.md))。
- **ジャーナル**: ワールドで評価したフォームの列。ワールドの状態を再現する手段になる。
- **micros**: Lem 版の SWANK。エディタとイメージの間のプロトコル。

## Clysm の性質と設計への帰結

| Clysm にあるもの | ADE での使い方 |
|---|---|
| イメージ内コンパイル(フォームごとに新しい Wasm モジュール) | 編集の単位は定義 1 つ。全体の再ビルドなしで試せる |
| micros / SWANK バックエンド(補完、引数リスト、`M-.`、インスペクタ、デバッガ、`macroexpand-all`) | エージェントは 2 人目の micros クライアントになる。新しいツール群を発明しない |
| コンディションと再起動、`sys::*record-frames*` のフレーム変数 | エラーは巻き戻さず、停止した状態をエージェントに渡す |
| `ui:define-command` の型付き引数、プレゼンテーション | コマンドがそのままエージェントのツール定義になり、画面上のオブジェクトが共有の参照になる |
| `ui:sexp-backend`(S 式の画面) | エージェントはスクリーンショットではなく S 式で GUI を見て `ui:fire` で操作する |
| グリーンスレッド、割り込み検査、10 ms のプリエンプション | エージェントの評価中もエディタが動き、人間が `C-c C-c` で止められる |
| ワーカーで動くイメージ | 使い捨てのワールドを並列に作り、複数の案を同時に試す |
| 全体コンパイル、`--shake`、`js:export` | 探索はライブで、検証と出荷は AOT で行う |
| SBCL と出力を比べるテスト | 差分テストを検証の標準手段にする |
| ブラウザ 1 ページで動く Lem | インストール不要の ADE。エージェントのループもページ内で動く |

## 構成

```
┌─ シェル(Electron / ブラウザのページ)────────────────────┐
│  エディタのイメージ: Lem + ui/ + エージェントのループ      │
│   ├─ 人間: Lem の Lisp モード ──┐                         │
│   └─ エージェント: スレッド ────┤ micros プロトコル        │
└────────────────────────────────┼─────────────────────────┘
                                 ▼
        ワールド(ワーカー内の Clysm イメージ)× N
        ├─ プロジェクトのコード + コンパイラ + micros
        ├─ ジャーナル(評価したフォームの列)
        └─ 権限: ホストが許したファイル・ネットワークだけ
                                 ▼
        検証: 全体コンパイル → clysm test → SBCL との差分
```

エディタとワールドは別のイメージにする。エージェントが書いたコードの無限ループや
ヒープの破壊にエディタを巻き込まないためである。micros は元々ソケット越しの
プロトコルなので、ソケットのスタブをワーカーとのメッセージにつなげば済む。

## 部品

### 1. ワールドとジャーナル

WasmGC のヒープは保存できないので、スナップショットは作れない。
そこで各ワールドは「基準のコミット + 評価したフォームの列」を持つ。

- 分岐は、新しいワールドでジャーナルを再生することである。
- 採用は、ジャーナルの定義を `clysm.sources` の位置情報でソースファイルに書き戻すことである。

ワールドの起動は実測で約 1.5 秒(micros の読み込みを含む)。ページのイメージの
コンパイル済みモジュールをワーカーに渡し、再コンパイルを省いている。この速さなら、
読み込み済みのワールドを常駐させるプールは当面いらない。プロジェクトのコードを
読み込む時間が加わったときに、改めて判断する。

### 2. エージェントのツール

micros の RPC に対応させる。

- `eval`、`compile-defun`: 評価とコンパイル。警告は構造化して返す。
- `describe`、`arglist`、`find-definition`、`who-calls`、`macroexpand-all`: 調査。
- `inspect`: オブジェクトをたどる。
- `disassemble`(`tools/dump-func.lisp` 相当)、`profile`(`tools/prof-script.sh` 相当): 性能の調査。
- `run-tests`: clysm-test をワールド内で実行する。

ファイルの読み書きは残すが主役ではない。エージェントは grep で推測する代わりに、
イメージに「この関数の呼び出し元は」と聞ける。

### 3. コマンドがツール、プレゼンテーションが参照

- `ui:command-parameters` の型から JSON Schema を生成し、アプリケーションのコマンドを
  自動でツールにする。コマンドパレットとツール一覧が同じものになる。
- 人間がプレゼンテーションをクリックすると、そのオブジェクトがエージェントの文脈に入る。
- エージェントの出力(関数名、テスト結果、フレーム)もプレゼンテーションとして表示し、
  右クリックでコマンドを出す。

### 4. 再起動を対話の手順にする

エージェントの評価でエラーが起きたら、ツールの結果として次を返す。

- コンディション
- フレームと局所変数
- 有効な再起動の一覧

エージェントは関数を直してから `retry` を選べる。長い計算をやり直さずに済む。
人間には同じ状態がデバッガで見えるので、途中から引き継げる。
破壊的な操作の確認も、人間が選ぶ再起動(`approve`、`deny`、`edit`)として実装する。

### 5. 権限

ワールドの外への出口はホストが渡す import だけなので、ワールドごとに許可を決められる
(読めるディレクトリ、書き込み、ネットワーク、サブプロセス)。
ただし `js:eval` と `js:global` はレルム全体に届くため、Lisp の側では制限できない。
境界はワーカーに置き、Node.js の permission model や、Node.js を持たないワーカーの
素の権限に頼る。

### 6. 並列の試行

スレッドはグリーンスレッドなので、並列性はワーカーの数で得る。
1 つの課題に対し複数のワールドで別の案を試し、テストとベンチマークを通った
ジャーナルだけを採用する。

### 7. 検証の 3 段階

| 段階 | 方法 | 用途 |
|---|---|---|
| 探索 | ライブ、フレーム記録あり | デバッグしやすいが、fib で約 13 倍遅い |
| 確認 | 新しいワールドでソースから全体コンパイルし `clysm test` | ジャーナルの順序に依存した偶然の成功を排除する |
| 差分 | 同じテストを SBCL で実行して出力を比べる | Clysm の不具合とプログラムの不具合を切り分ける |

「確認」を通らない変更はコミットしない。ライブイメージでの開発には、イメージでは
動くのにソースからは動かないという罠があり、これをエージェントに踏ませないためである。

### 8. 画面

Lem のウィンドウに `ui/` のペインを 3 つ足す。

- エージェントとの会話(`ui/stream.lisp` のインタラクタが土台)
- ワールドの一覧と、各ジャーナルの差分
- 停止中の計算(デバッガ)の一覧

## 制約

- **速度**: フォームごとのロードは全体コンパイルより 1.8〜2.9 倍遅い。
  性能の判断は「確認」段階の数値だけで行う。
- **ブラウザ版**: サブプロセスも SBCL もないので差分テストはできない。
  API キーをページに置く問題もある。最初はデスクトップ版に絞る。
- **深い再帰**: スタックを使い切る再帰は、応答もデバッガもなく評価が終わる
  (エディタのイメージでも同じ)。エージェントには原因が見えないので、
  ステップ 2 までにエラーとして返るようにする必要がある。
- **割り込み検査のないコード**: 接続前にコンパイルされたコードのループは
  `C-c C-c` で止まらない。ワールドを終了させることになる。

## 作る順序

1. **ワールド**(実装済み、コミット 26e9699): エディタと別のイメージに
   Lem の Lisp モードで接続する。`M-x world-start`、`M-x world-kill`。
   デスクトップ版のみ。
2. **エージェントのループとツール**: micros クライアントとして実装し、
   エラーを再起動付きで返すところまで作る。
3. **ジャーナルと書き戻し、「確認」段階**: ここで初めてエージェントの変更をコミットできる。
4. **コマンドのツール化、プレゼンテーションの共有、S 式での GUI 操作**。
5. **並列のワールドと権限**。
